# 五阶段分析进度控制功能说明

## 功能概述

本次更新为"运行五阶段分析"功能添加了完整的进度可视化和控制能力，包括：

1. ✅ **实时进度显示** - 显示当前阶段、批次、LLM调用次数等
2. ✅ **暂停/继续** - 可以随时暂停和恢复分析
3. ✅ **取消分析** - 可以立即停止正在运行的分析
4. ✅ **防止重复点击** - 避免意外产生多次API费用
5. ✅ **费用确认** - 开始前弹出确认对话框
6. ✅ **持久化进度** - 刷新页面或切换标签页后进度不丢失
7. ✅ **后台轮询** - 即使切换到其他页面也会持续更新进度

## API端点

### 1. 获取分析进度
```
GET /api/legacy/analyze/progress?project=<project_name>
```

返回示例：
```json
{
  "project": "投放管理平台",
  "status": "running",
  "current_stage": 2,
  "total_stages": 5,
  "stage_name": "信号抽取（LLM）",
  "total_batches": 875,
  "completed_batches": 123,
  "current_batch": 123,
  "batch_type": "case",
  "llm_calls": 123,
  "extracted_signals": 456,
  "elapsed_seconds": 245.3,
  "message": "已完成 123/875 总批次",
  "error": null,
  "progress_percent": 28.0
}
```

### 2. 暂停分析
```
POST /api/legacy/analyze/pause?project=<project_name>
```

### 3. 继续分析
```
POST /api/legacy/analyze/resume?project=<project_name>
```

### 4. 取消分析
```
POST /api/legacy/analyze/cancel?project=<project_name>
```

## 使用流程

### 1. 启动分析

1. 在"目录管理" → "历史用例"页面
2. 点击"运行五阶段分析"按钮
3. 弹出确认对话框，显示将调用LLM API并产生费用
4. 确认后开始分析

### 2. 查看进度

分析开始后，会显示进度卡片，包含：

- **进度条** - 可视化显示总体进度百分比
- **当前阶段** - 显示正在执行的阶段名称（1-5）
- **批次信息** - 显示已完成的批次数/总批次数
- **LLM调用次数** - 实时统计LLM API调用次数
- **提取信号数** - 已成功提取的信号数量
- **耗时** - 已运行的时间（分钟:秒）

### 3. 控制分析

在分析过程中，可以使用以下按钮：

- **暂停** - 暂停当前分析（会在当前批次完成后暂停）
- **继续** - 从暂停处继续分析
- **取消** - 立即停止分析（需要二次确认）

### 4. 完成/错误

分析完成后：
- 进度卡片自动消失
- 显示完成消息（用例数、节点数、LLM调用数、反哺数）
- 如果有错误，会显示错误信息

## 状态说明

| 状态 | 说明 |
|------|------|
| `idle` | 空闲，没有正在进行的分析 |
| `running` | 正在运行 |
| `paused` | 已暂停 |
| `cancelled` | 已取消 |
| `completed` | 已完成 |
| `error` | 出错 |

## 阶段说明

| 阶段 | 名称 | 说明 |
|------|------|------|
| 1 | 标准化数据 | 加载用例和XMind数据 |
| 2 | 信号抽取（LLM） | 调用LLM进行信号抽取（最耗时） |
| 3 | 计算风格画像 | 分析用例风格特征 |
| 4 | 聚合信号 | 聚合提取的信号 |
| 5 | 生成反哺候选 | 生成知识点候选 |

## 注意事项

### 1. 费用控制

- 每次点击都会弹出确认对话框
- 进度面板实时显示LLM调用次数
- 可以随时取消以避免费用继续增加

### 2. 持久化机制

**进度会自动保存**：
- 使用浏览器 localStorage 保存进度状态
- 刷新页面后自动恢复进度显示
- 切换到其他项目或标签页后再回来，进度仍在
- 数据有效期：1小时（超过1小时会自动清除）

**恢复逻辑**：
1. 组件挂载时检查 localStorage
2. 如果有保存的进度，立即显示
3. 向后端查询最新状态
4. 如果仍在运行，启动轮询继续更新
5. 如果已完成，清除状态

**状态指示**：
- 🟢 **后台运行中** - 分析正在后端执行
- 🟡 **已暂停** - 分析已暂停，等待继续

### 3. 暂停机制

- 暂停不是立即的，会在当前批次处理完成后才暂停
- 暂停期间不会调用LLM，不会产生费用
- 可以继续或取消

### 4. 取消机制

- 取消需要二次确认
- 取消后已处理的数据会丢失
- 已调用的LLM费用无法退还

### 5. 防止重复

- 分析进行中时，按钮会被禁用
- 即使快速多次点击也只会执行一次
- 刷新页面后会从 localStorage 恢复状态

### 6. 浏览器兼容性

- 需要支持 localStorage（所有现代浏览器都支持）
- 建议使用 Chrome、Firefox、Edge 等主流浏览器
- Safari 在无痕模式下可能禁用 localStorage

## 技术实现

### 后端

1. **AnalysisController** - 每个项目一个控制器实例
2. **线程安全** - 使用锁保护共享状态
3. **暂停机制** - 使用Event实现线程等待
4. **取消标志** - 在每个批次间检查取消标志

### 前端

1. **轮询机制** - 每2秒查询一次进度
2. **状态管理** - 使用React state管理进度
3. **自动清理** - 分析完成后自动停止轮询
4. **响应式UI** - 根据状态显示不同按钮
5. **持久化存储** - 使用localStorage保存进度状态
6. **自动恢复** - 组件挂载时从localStorage恢复进度
7. **过期清理** - 超过1小时的进度数据自动清除

## 故障排查

### 问题1：进度不更新

**原因**：后端服务未重启，新代码未生效

**解决**：
```bash
# 重启后端服务
python run.py
```

### 问题2：刷新页面后进度消失

**原因1**：localStorage被禁用或清除

**解决**：
- 检查浏览器是否禁用了localStorage
- 不要在无痕模式下使用
- 清除浏览器缓存后重新运行分析

**原因2**：进度数据已过期（超过1小时）

**解决**：
- 这是正常行为，过期的进度会自动清除
- 如果分析仍在后台运行，可以手动查询进度

### 问题3：暂停无效

**原因**：当前批次正在处理LLM请求，需要等待完成

**解决**：耐心等待当前批次完成（通常几秒到几十秒）

### 问题4：取消后仍在运行

**原因**：取消标志只在批次间检查

**解决**：等待当前批次完成后会自动停止

### 问题5：前端显示错误

**原因**：浏览器缓存了旧代码

**解决**：
1. 硬刷新页面（Ctrl+F5）
2. 清除浏览器缓存
3. 打开开发者工具，禁用缓存

### 问题6：localStorage保存失败

**原因**：
- 浏览器禁用了localStorage
- 存储空间已满
- 在无痕模式下运行

**解决**：
1. 检查浏览器设置，启用localStorage
2. 清除部分浏览器数据释放空间
3. 使用正常模式而非无痕模式
4. 即使localStorage失败，分析仍会继续运行，只是刷新后无法恢复进度

## 性能优化建议

### 对于大数据量（>1000条用例）

1. **使用skip_extract模式**
   ```javascript
   // 只计算风格画像，不调用LLM
   await api.legacyAnalyze(project, llm, { skip_extract: true });
   ```

2. **分批处理**
   - 先处理部分数据测试
   - 确认效果后再处理全部

3. **选择更快的模型**
   - 使用 GPT-4o-mini 而非 GPT-4o
   - 成本降低约90%

4. **设置预算警报**
   - 在OpenAI平台设置月度预算
   - 启用使用量警报
