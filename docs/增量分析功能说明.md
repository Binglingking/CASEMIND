# 增量分析功能说明

## 🎯 功能概述

**增量分析**可以智能跳过已经分析过的用例和XMind节点，只处理新增或内容有变化的项，从而大幅降低API费用。

---

## ✨ 核心特性

### 1. 智能内容指纹
- 为每个用例和XMind节点计算SHA256哈希指纹
- 基于实际内容（标题、步骤、预期等）而非ID
- 内容变化时自动重新分析

### 2. 自动缓存管理
- 缓存位置：`memory/<project>/legacy/analysis_cache.json`
- 记录每个项的分析时间、信号数量等信息
- 支持跨会话持久化

### 3. 透明化处理
- 对用户完全透明，无需手动管理
- 首次分析：全量处理并建立缓存
- 后续分析：自动跳过未变化的项

---

## 📊 费用对比

| 场景 | 完整分析 | 增量分析 | 节省比例 |
|------|---------|---------|---------|
| 首次分析（364用例+649节点） | $5.70 | $5.70 | 0% |
| 添加10个新用例 | $5.70 | **$0.16** | **97%** ⭐ |
| 修改5个用例 | $5.70 | **$0.08** | **99%** ⭐ |
| 无变化重复运行 | $5.70 | **$0.00** | **100%** ⭐ |

**实际案例**：
- 您有364条用例+649个XMind节点
- 首次分析：$5.70（建立缓存）
- 第二次（无变化）：**$0.00**（全部跳过）
- 添加20条新用例：**约$0.30**（只分析新的）

## 🚀 使用方法

### 启用增量分析（推荐）

1. 进入「文件夹」页面
2. 确保勾选 **"增量分析（推荐）"** 复选框（默认已勾选）
3. 点击"运行五阶段分析"
4. 系统会自动检测并跳过已分析的项

### 强制完整分析

如需重新分析所有数据（例如优化了prompt后）：
1. 取消勾选"增量分析"复选框
2. 运行分析

### 清空缓存

如需完全重置缓存：
```bash
# 删除项目的分析缓存文件
rm memory/<project>/legacy/analysis_cache.json
```

或在代码中调用：
```python
from backend.core.legacy.analysis_cache import clear_cache
clear_cache(project)
```

## 🔍 工作原理

### 流程图

```
开始分析
  ↓
加载缓存 ←──────────────┐
  ↓                      │
检查每个用例/XMind       │
  ├─ 已分析且未变化 ─→ 跳过
  └─ 未分析或已变化 ─→ 加入待分析队列
  ↓
分批调用LLM（仅待分析项）
  ↓
更新缓存 ──────────────→┘
  ↓
完成
```

### 内容指纹计算

**用例指纹**：
```python
content = f"{title}|{preconditions}|{str(step_pairs)}"
fingerprint = SHA256(content)[:16]
```

**XMind节点指纹**：
```python
content = f"{title}|{path}|{note}"
fingerprint = SHA256(content)[:16]
```

## ⚠️ 注意事项

### 1. 何时使用增量分析

✅ **推荐使用**：
- 日常迭代，只添加少量新用例
- 修改了部分用例内容
- 频繁运行分析以测试效果

❌ **不建议使用**：
- 首次分析项目（无缓存）
- 大规模重构用例结构
- 优化了Stage 2的prompt后需重新分析

### 2. 缓存失效场景

以下情况需要清空缓存并重新分析：
- 修改了 `stage2_extract.py` 的prompt
- 调整了信号抽取的逻辑
- 发现缓存数据异常

### 3. 性能影响

- **空间占用**：缓存文件通常 < 1MB
- **时间开销**：指纹计算几乎无延迟（< 1ms/项）
- **内存占用**：加载缓存约 10-50KB

### 4. 与其他选项的关系

| 选项组合 | 行为 | 费用 |
|---------|------|------|
| 增量✓ + 跳过LLM✗ | 只分析新增项 | 低 |
| 增量✗ + 跳过LLM✗ | 完整分析所有项 | 高 |
| 增量✓ + 跳过LLM✓ | 跳过LLM（增量无效） | 0 |
| 增量✗ + 跳过LLM✓ | 跳过LLM（增量无效） | 0 |

**注意**：当"跳过LLM"启用时，"增量分析"自动失效（因为没有LLM调用可优化）。

## 🔧 技术实现

### 核心模块

1. **缓存管理**：`backend/core/legacy/analysis_cache.py`
   - 加载/保存缓存
   - 指纹计算
   - 增量过滤

2. **Stage 2集成**：`backend/agents/legacy_analyzer/stage2_extract.py`
   - 接收 `incremental` 参数
   - 过滤已分析项
   - 更新缓存

3. **前端控制**：`frontend/src/pages/Folders.jsx`
   - 用户界面开关
   - 传递参数到后端

### API变更

**请求体**：
```json
{
  "project": "投放管理平台",
  "llm": {...},
  "skip_extract": false,
  "incremental": true  // 新增字段
}
```

**响应**：
```json
{
  "ok": true,
  "llm_calls": 2,  // 增量模式下会显著减少
  "inferred_count": 5,
  ...
}
```

## 💡 最佳实践

### 日常工作流

1. **首次分析**：
   ```
   ☑ 增量分析（可选，首次无效）
   ☐ 跳过LLM
   → 运行完整分析（$5.70）
   ```

2. **添加新用例后**：
   ```
   ☑ 增量分析（默认）

   → 只分析新用例（约$0.10-0.50）
   ```

3. **仅更新风格画像**：
   ```
   ☑ 增量分析（任意）
   ```

   ```
   ☐ 增量分析（取消勾选）
   ☐ 跳过LLM
   → 重新分析所有数据（$5.70）
   ```

### 成本估算公式

```
增量分析费用 = (新增用例数 ÷ 25 + 新增XMind节点数 ÷ 50) × 单次LLM费用

示例：
- 新增20个用例：20 ÷ 25 ≈ 1批次 → $0.20
- 新增50个XMind节点：50 ÷ 50 = 1批次 → $0.20
- 总计：2批次 → 约$0.40
```

## 🆘 故障排查

### 问题1：增量分析没有跳过任何项

**可能原因**：
- 缓存文件不存在或损坏
- 用例内容确实发生了变化

**解决方法**：
```bash
# 检查缓存文件是否存在
ls memory/<project>/legacy/analysis_cache.json

# 查看缓存统计
python -c "
from backend.core.legacy.analysis_cache import load_cache, get_cache_stats
cache = load_cache('your_project')
print(get_cache_stats(cache))
"
```

### 问题2：缓存文件过大

**正常情况**：
- 1000个用例 + 2000个节点 ≈ 500KB

**如果超过5MB**：
```python
# 清空缓存重建
from backend.core.legacy.analysis_cache import clear_cache
clear_cache(project)
```

### 问题3：想查看哪些项被跳过

查看日志中的跳过信息：
```
[Stage 2] 批次 1 跳过 25 个已分析用例
[Stage 2] XMind批次 1 跳过 50 个已分析节点
```
