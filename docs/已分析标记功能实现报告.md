# 已分析标记功能实现报告

## 🎯 需求背景

用户希望为已经运行过五阶段分析的XMind和用例文件打上标记，达到两个目的：

1. **给用户参考**：让用户心里有数，知道哪些文件已经分析过
2. **给AI参考**：在增量检测时注意跳过已分析的文件

---

### 2. 后端逻辑：分析完成后自动标记

**文件1**：`backend/agents/legacy_analyzer/runner.py`

在五阶段分析完成后（Stage 5之后），自动标记所有参与分析的文件：

```python
# Save style profile
profile = StyleProfile(...)
legacy_store.save_style_profile(project, profile)

# ✅ 标记所有用例文件和XMind文件为已分析
from backend.core.timeutil import utc_iso_z
analyzed_at = utc_iso_z()

# 更新用例文件标记
for case_file in legacy_store.list_case_files(project):
    case_file.analyzed = True
    case_file.analyzed_at = analyzed_at
    legacy_store.upsert_case_file(project, case_file, legacy_store.load_cases(project, case_file.file_id))

# 更新XMind文件标记
for xmind_file in legacy_store.list_xmind_files(project):
    tree = legacy_store.load_xmind_tree(project, xmind_file['file_id'])
    if tree:
        tree.analyzed = True
        tree.analyzed_at = analyzed_at
        legacy_store.upsert_xmind_tree(project, tree)
```

**工作原理**：
- 每次运行五阶段分析后，遍历项目中所有的用例文件和XMind文件
- 将它们的`analyzed`字段设为`True`
- 记录分析时间`analyzed_at`
- 持久化到JSON文件中

**文件2**：`backend/core/legacy/legacy_store.py`

修复XMind文件索引，确保`analyzed`和`analyzed_at`字段被包含在索引中：

```python
def upsert_xmind_tree(project: str, tree: LegacyXMindTree) -> None:
    idx = [f for f in list_xmind_files(project) if f.get("file_id") != tree.file_id]
    idx.append({
        "file_id": tree.file_id,
        "name": tree.name,
        "ext": tree.ext,
        "size": tree.size,
        "mtime": tree.mtime,
        "uploaded_at": tree.uploaded_at,
        "node_count": len(tree.nodes),
        "analyzed": tree.analyzed,          # ✅ 新增
        "analyzed_at": tree.analyzed_at,    # ✅ 新增
    })
    save_xmind_files_index(project, idx)
    _write_json(
        legacy_dir(project) / "xmind" / f"{tree.file_id}.json",
        tree.model_dump(),
    )
```

**问题说明**：
- XMind文件有两个存储位置：
  1. `xmind.json` - 文件索引（列表视图使用）
  2. `xmind/<file_id>.json` - 完整树数据（详情视图使用）
- 之前`upsert_xmind_tree`只更新了完整树数据，没有更新索引中的`analyzed`字段
- 导致前端列表无法显示标记
- 修复后，索引和完整数据都包含标记字段

### 向后兼容

- `analyzed`字段默认为`False`
- `analyzed_at`字段默认为`None`
- 旧文件没有这些字段时，Pydantic会自动填充默认值
- 不会破坏现有数据

### 步骤3：历史数据同步

如果您之前已经运行过五阶段分析，但文件没有显示标记，可以运行精确同步脚本：

```bash
python sync_analyzed_marks_precise.py <project_name>
```

**同步逻辑**：
- 检查增量分析缓存（`analysis_cache.json`）中的用例ID和XMind节点ID
- 检查反哺候选（`inferred_kps.json`）的source信息
- 从case_id中提取file_id（格式：`LC_<file_id>_<row>`）
- 精确判断哪些文件真正被分析过
- 为已分析的文件添加标记，清除错误标记

**示例**：
```bash
python sync_analyzed_marks_precise.py 投放管理平台
```
