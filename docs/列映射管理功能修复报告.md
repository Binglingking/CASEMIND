# 列映射管理功能修复报告

## 🔍 问题描述

用户反馈：上传Excel文件后，点击"列映射管理"按钮，显示"尚无任何列映射记录 — 上传一份 Excel 后会自动出现在这里"，但实际上已经上传过Excel文件。

---

## 🐛 根本原因

### 1. 后端未保存自动推断的列映射

**文件**：`backend/services/legacy_service.py`

**问题代码**（第125-147行）：

```python
mapping: ColumnMapping
if confirmed_mapping is not None:
    # 用户确认的映射 → 保存 ✓
    mapping = confirmed_mapping
    mapping.confirmed = True
    store_obj.by_fingerprint[fp] = mapping
    legacy_store.save_column_mapping_store(project, store_obj)
elif fp in store_obj.by_fingerprint and store_obj.by_fingerprint[fp].confirmed:
    # 已有确认的映射 → 复用 ✓
    mapping = store_obj.by_fingerprint[fp]
else:
    # 自动推断
    auto = auto_map(headers, extra_synonyms=store_obj.extra_synonyms)
    if needs_ai_assist(auto) and not (fp in store_obj.by_fingerprint):
        # 命中率不足 → 返回让用户确认 ✓
        return ExcelIngestResult(..., needs_user_confirm=True, ...)
    mapping = auto
    # ❌ 问题：自动推断成功但没有保存到store！
```

**后果**：
- 如果Excel表头命中率高（≥阈值），自动推断成功
- 解析用例成功，但**列映射没有被保存到`column_mapping.json`**
- 前端"列映射管理"对话框看不到任何记录

### 2. 前端未刷新列映射存储

**文件**：`frontend/src/pages/Folders.jsx`

**问题代码**（第449-471行）：

```javascript
async function uploadOne(file, confirmedMapping = null) {
  const r = await api.legacyUploadCase(project, file, confirmedMapping);
  if (r.needs_user_confirm) {
    // 弹出确认对话框 ✓
  } else if (r.already_parsed) {
    // 已存在，跳过 ✓
  } else {
    // 解析成功
    setMsg(`已解析 ${r.case_count} 条用例`);
    await refresh();  // 只刷新文件列表
    // ❌ 问题：没有调用loadMappingStore()刷新列映射
  }
}
```

**后果**：
- 即使后端保存了列映射，前端也不会立即更新
- 用户需要手动点击"列映射管理"按钮才会加载最新数据
- 但由于后端根本没保存，所以始终为空

---

## ✅ 修复方案

### 修复1：后端保存自动推断的列映射

**文件**：`backend/services/legacy_service.py`

**修改位置**：第147行之后

**修改前**：
```python
mapping = auto
# 解析...
```

**修改后**：
```python
mapping = auto
# 自动推断成功，保存到store（但未确认）
if fp not in store_obj.by_fingerprint:
    store_obj.by_fingerprint[fp] = mapping
    legacy_store.save_column_mapping_store(project, store_obj)
# 解析...
```

**效果**：
- 自动推断成功的列映射会被保存到`column_mapping.json`
- `confirmed=False`表示是自动推断的，不是用户确认的
- 下次上传相同表头的文件会直接复用

### 修复2：前端上传成功后刷新列映射存储

**文件**：`frontend/src/pages/Folders.jsx`

**修改位置**：第467行之后

**修改前**：
```javascript
setMsg(`已解析 ${r.case_count} 条用例 ${warn}`);
setTimeout(() => setMsg(''), 3000);
await refresh();
```

**修改后**：
```javascript
setMsg(`已解析 ${r.case_count} 条用例 ${warn}`);
setTimeout(() => setMsg(''), 3000);
await refresh();
// 上传成功后刷新列映射存储
await loadMappingStore();
```

**修改位置**：第481-489行（confirmMapping函数）

**修改前**：
```javascript
async function confirmMapping(payload) {
  await api.legacyConfirmColumnMapping(project, fingerprint, mapping);
  await uploadOne(pendingFile.file, mapping);
  setPendingFile(null);
}
```

**修改后**：
```javascript
async function confirmMapping(payload) {
  await api.legacyConfirmColumnMapping(project, fingerprint, mapping);
  // 先更新列映射存储
  await loadMappingStore();
  // 再上传文件（uploadOne内部会再次刷新，但没关系，确保数据最新）
  await uploadOne(pendingFile.file, mapping);
  setPendingFile(null);
}
```

**效果**：
- 上传Excel后立即刷新前端的mappingStore状态
- 用户打开"列映射管理"对话框能看到最新的记录

## 💡 技术细节

### 列映射存储结构

**文件**：`memory/<project>/legacy/column_mapping.json`

**结构**：
```json
{
  "by_fingerprint": {
    "a1b2c3d4e5f6": {
      "header_to_standard": {
        "用例名称": "用例名称",
        "操作步骤": "用例步骤",
        "期望结果": "预期结果"
      },
      "unmapped_headers": ["备注", "JIRA单号"],
      "confirmed": false,
      "hit_ratio": 0.8
    }
  },
  "stage_suffixes": [
    "前置准备", "正常流程", "异常流程", 
    "边界情况", "兼容性", "安全性", "性能"
  ],
  "extra_synonyms": {}
}
```

**关键字段**：
- `by_fingerprint`: 按表头指纹索引的映射字典
- `fingerprint`: 表头原文按字母序拼接后的sha1[:12]
- `confirmed`: 是否经过用户确认
- `hit_ratio`: 标准列被映射上的比例（0~1）

### 工作流程

```
用户上传Excel
    ↓
读取表头 → 计算fingerprint
    ↓
检查缓存
    ├─ 有confirmed映射 → 直接复用
    ├─ 无缓存或命中率低 → 弹出确认对话框
    │   └─ 用户确认 → 保存confirmed映射
    └─ 无缓存但命中率高 → 自动推断
        └─ 保存unconfirmed映射 ← 修复点1
    ↓
解析用例
    ↓
保存用例数据
    ↓
刷新前端状态 ← 修复点2
```
