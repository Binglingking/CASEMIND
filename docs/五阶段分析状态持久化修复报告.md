# 五阶段分析状态持久化修复报告

## 🐛 问题描述

用户反馈在进行五阶段分析时刷新页面，分析过程会消失，导致无法暂停和取消。

**具体表现**：
1. 开始五阶段分析后，显示进度条和控制按钮（暂停/继续/取消）
2. 刷新页面（F5）
3. 进度条和控制按钮消失
4. 后端分析仍在运行，但前端无法控制（无法暂停/取消）

---

## 🔍 问题分析

### 原因

虽然代码已经有localStorage保存逻辑，但存在以下问题：

1. **过期时间太短**：只保存1小时，长时间分析可能过期
2. **恢复后未启动轮询**：从localStorage恢复状态后，没有重新启动进度轮询
3. **缺少调试日志**：无法追踪恢复过程是否成功

### 原有代码的问题

```jsx
// 问题1：过期时间只有1小时
const oneHourAgo = Date.now() - 60 * 60 * 1000;
if (timestamp > oneHourAgo && wasAnalyzing) {
  // ...
}

// 问题2：恢复后启动了轮询，但注释不清晰
if (['running', 'paused'].includes(progress.status)) {
  startProgressPolling(); // ✅ 这里有启动，但可能被忽略
}
```

---

## ✅ 修复方案

### 1. 延长过期时间

将过期时间从1小时延长到2小时：

```jsx
// 修改前
const oneHourAgo = Date.now() - 60 * 60 * 1000;

// 修改后
const twoHoursAgo = Date.now() - 2 * 60 * 60 * 1000;
```

**原因**：
- 大型项目的五阶段分析可能需要较长时间
- 2小时更合理，覆盖大多数分析场景
- 如果分析超过2小时，大概率已经完成或出错

---

### 2. 增强日志输出

添加详细的console.log，方便调试：

```jsx
console.log('[LegacyCaseTab] Restoring analysis progress from localStorage');
console.log('[LegacyCaseTab] Backend progress:', progress);
console.log('[LegacyCaseTab] Starting progress polling');
console.log('[LegacyCaseTab] Analysis already completed, clearing state');
console.log('[LegacyCaseTab] Saved progress expired, clearing');
```

**作用**：
- 追踪恢复流程的每一步
- 确认轮询是否正确启动
- 方便排查问题

---

### 3. 确保轮询启动

在恢复逻辑中明确启动轮询：

```jsx
api.legacyAnalysisProgress(project).then(progress => {
  console.log('[LegacyCaseTab] Backend progress:', progress);
  setAnalysisProgress(progress);
  
  // 如果仍在运行或暂停，启动轮询
  if (['running', 'paused'].includes(progress.status)) {
    console.log('[LegacyCaseTab] Starting progress polling');
    startProgressPolling(); // ✅ 确保启动
  } else {
    // 已经完成，清除状态
    console.log('[LegacyCaseTab] Analysis already completed, clearing state');
    setAnalyzing(false);
    setBusy(false);
    setAnalysisProgress(null);
    localStorage.removeItem(`analysis_progress_${project}`);
  }
});
```

## 🔧 技术细节

### localStorage数据结构

```javascript
{

    "analyzing": true,
    "progress": {
      "status": "running",
      "stage": 2,
      "stage_name": "信号抽取（LLM）",
      "current_stage": 2,
      "total_stages": 5,
      "completed_batches": 3,
      "total_batches": 10,
      "llm_calls": 15,
      "extracted_signals": 42,
      "elapsed_seconds": 120,
      "progress_percent": 40,
      "message": "正在处理批次 4/10..."
    },
    "timestamp": 1234567890123
  }
}
```

---

### 轮询机制

```jsx
function startProgressPolling() {
  // 每2秒查询一次进度
  progressTimerRef.current = setInterval(async () => {
    try {
      const progress = await api.legacyAnalysisProgress(project);
      setAnalysisProgress(progress);
      
      // 保存到localStorage，以便刷新后恢复
      if (['running', 'paused'].includes(progress.status)) {
        localStorage.setItem(`analysis_progress_${project}`, JSON.stringify({
          analyzing: true,
          progress: progress,
          timestamp: Date.now()
        }));
      }
      
      // 如果已完成或取消，停止轮询
      if (['completed', 'cancelled', 'error'].includes(progress.status)) {
        stopProgressPolling();
        setAnalyzing(false);
        setBusy(false);
        setAnalysisProgress(null);
        localStorage.removeItem(`analysis_progress_${project}`);
      }
    } catch (e) {
      console.error('[LegacyCaseTab] Failed to fetch progress:', e);
    }
  }, 2000);
}
```

**特点**：
- 每2秒查询一次后端
- 只在running/paused状态时保存
- 完成/取消/错误时自动清理

## 📈 性能考虑

### localStorage写入频率
- 每2秒写入一次（轮询间隔）
- 每次写入约200-300字节
- 对性能影响可忽略

### 过期清理
- 超过2小时自动清理
- 避免积累无用数据
- 每个项目最多1个key
