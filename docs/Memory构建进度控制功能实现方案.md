# Memory构建进度控制功能实现方案

## 📋 功能概述

为"构建AI记忆"功能添加完整的进度可视化和控制能力，包括：

1. ✅ **实时进度显示** - 显示当前步骤、文件处理数、LLM调用次数等
2. ✅ **暂停/继续** - 可以随时暂停和恢复构建
3. ✅ **取消构建** - 可以安全停止正在运行的构建（不影响已有memory）
4. ✅ **防止重复点击** - 避免意外触发多次构建
5. ✅ **持久化进度** - 刷新页面后进度不丢失（通过后端状态）

## 🎯 核心设计原则

### 1. 安全性优先
- **取消构建不会影响已有memory**：取消时保留已生成的memory.md和prompt
- **增量构建保护**：如果用户之前有memory，取消后仍然保留
- **版本回滚支持**：利用现有的版本系统，可以在需要时恢复到之前的版本

### 2. 用户体验
- 类似五阶段分析的进度展示
- 清晰的步骤说明和进度百分比
- 实时更新的统计数据

## 🔌 API端点

### 1. 获取构建进度
```
GET /api/memory/build/progress?project=<project_name>
```

返回示例：
```json
{
  "project": "投放管理平台",
  "status": "running",
  "current_step": 3,
  "total_steps": 6,
  "step_name": "合成 memory.md",
  "processed_files": 45,

  "llm_calls": 48,

  "elapsed_seconds": 125.3,
  "message": "正在处理第 45/120 个文件...",
  "error": null,

```

### 2. 暂停构建
```
POST /api/memory/build/pause?project=<project_name>
```

### 3. 继续构建
```
POST /api/memory/build/resume?project=<project_name>
```

### 4. 取消构建
```
POST /api/memory/build/cancel?project=<project_name>
```

## 🔄 构建步骤说明

| 步骤 | 名称 | 说明 |
|------|------|------|
| 1 | 扫描文件夹 | 扫描所有配置的文件夹，检测文件变化 |
| 2 | 检测删除文件 | 从索引中移除已删除的文件 |
| 3 | 处理新增/变更文件 | 解析、分块、向量化、生成摘要（最耗时） |
| 4 | 保存文件索引 | 更新file_index.json |
| 5 | 合成 memory.md | 调用LLM合成系统记忆 |
| 6 | 生成 prompt | 基于memory.md生成memory_prompt.txt |
| 7 | 知识抽取(可选) | 如果启用了enable_knowledge_extraction |

## 💡 使用流程

### 1. 启动构建

1. 在"记忆面板"页面
2. 选择构建模式（增量/全量）
3. 点击"构建 AI 记忆"按钮
4. 开始构建并显示进度

### 2. 查看进度

构建开始后，会显示进度卡片，包含：

- **进度条** - 可视化显示总体进度百分比
- **当前步骤** - 显示正在执行的步骤名称（1-6）
- **文件信息** - 显示已处理的文件数/总文件数
- **LLM调用次数** - 实时统计LLM API调用次数
- **抽取知识点数** - 已成功抽取的知识点数量
- **耗时** - 已运行的时间（分钟:秒）

### 3. 控制构建

在构建过程中，可以使用以下按钮：

- **暂停** - 暂停当前构建（会在当前文件处理完成后暂停）
- **继续** - 从暂停处继续构建
- **取消** - 立即停止构建（需要二次确认，保留已有memory）

### 4. 完成/错误

构建完成后：
- 进度卡片自动消失
- 显示完成消息（新增/更新/跳过/删除文件数）
- 如果有错误，会显示错误信息

## ⚙️ 状态说明

| 状态 | 说明 |
|------|------|
| `idle` | 空闲，没有正在进行的构建 |
| `running` | 正在运行 |
| `paused` | 已暂停 |
| `cancelled` | 已取消（保留已有memory） |
| `completed` | 已完成 |
| `error` | 出错 |

## 🛡️ 安全机制

### 1. 取消保护
当用户点击"取消"时：
1. 立即停止后续处理
2. **保留已生成的memory.md和prompt**
3. 如果构建了新版本，可以通过版本历史回滚
4. 清除进度跟踪器状态

### 2. 版本保护
- 每次构建前自动创建版本快照
- 取消后可以恢复到之前的版本
- 用户手动编辑的记忆不会被覆盖

### 3. 增量构建保护
- 增量模式下，未处理的文件保持原样
- 已处理的文件会被保存
- 取消后下次可以继续增量构建

## 🔧 技术实现要点

### 1. 后端进度跟踪
- 使用线程安全的控制器管理
- 支持多项目并发构建
- 定期检查暂停/取消标志

### 2. 暂停机制
- 在文件处理循环的关键检查点检查暂停标志
- 暂停时记录已处理的状态
- 继续时从断点恢复

### 3. 取消机制
- 立即设置取消标志
- 在下一个检查点停止处理
- 保留已完成的work（memory.md、向量索引等）
- 清理进度跟踪器

### 4. 前端轮询
- 每2秒查询一次进度
- 保存到localStorage以便刷新后恢复
- 完成/取消/错误时自动清理

## 📝 注意事项

### 1. 费用控制
- 进度面板实时显示LLM调用次数
- 可以随时取消以避免费用继续增加
- 暂停期间不会调用LLM

### 2. 数据一致性
- 取消后可能留下部分更新的索引
- 下次构建会自动修复不一致
- 建议取消后重新运行一次完整构建

### 3. 性能考虑
- 进度更新不应影响构建性能
- 使用异步更新，不阻塞主流程
- 日志记录最小化

## ✨ 与五阶段分析的区别

| 特性 | 五阶段分析 | Memory构建 |
|------|-----------|-----------|
| 数据来源 | 历史用例/XMind | 配置文件夹中的文档 |
| 处理对象 | 用例和节点 | 文档文件和chunks |
| 输出 | 反哺候选 | memory.md + prompt |
| 取消影响 | 丢失已处理数据 | 保留已有memory |
| 可恢复性 | 需重新开始 | 可增量继续 |
