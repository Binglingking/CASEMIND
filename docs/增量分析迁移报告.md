## ⚠️ 注意事项

### 1. 缓存准确性

迁移的缓存是从反哺候选反推的，可能存在以下情况：

✅ **准确的部分**：
- 用例ID和XMind节点ID正确
- 分析时间戳正确
- 基本内容指纹已建立

⚠️ **可能的偏差**：
- 某些用例可能没有生成反哺候选，因此未被缓存
- 内容指纹是基于有限信息构建的，可能与实际略有差异

### 2. 如果发现遗漏

如果运行时发现某些已分析的项没有被跳过，这是正常的，因为：
- 只有生成了反哺候选的项才会被迁移
- 没有反哺候选的用例/XMind需要首次分析

**解决方案**：
- 运行一次完整的增量分析（不勾选"跳过LLM"）
- 这次会分析所有未缓存的项并更新缓存
- 之后就完全准确了

### 3. 清空缓存

如果需要重新开始：

```bash
# 删除缓存文件
rm memory/投放管理平台/legacy/analysis_cache.json

# 或在Python中
from backend.core.legacy.analysis_cache import clear_cache
clear_cache('投放管理平台')
```

## 📝 技术细节

### 迁移脚本

位置：`backend/core/legacy/migrate_cache_to_incremental.py`

使用方法：
```bash
python -m backend.core.legacy.migrate_cache_to_incremental <project>
```

### 迁移逻辑

1. **加载反哺候选**：从 `inferred_kps.json` 读取所有历史反哺候选
2. **提取Source信息**：遍历每个候选，提取 `source.case_id` 或 `source.node_id`
3. **构建内容指纹**：
   - 用例：`{title}|{preconditions}|{steps}`
   - XMind：`node:{node_id}|{path}`
4. **写入缓存**：保存到 `analysis_cache.json`
