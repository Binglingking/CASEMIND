# 增量分析问题修复报告

## 🔍 问题描述

用户反馈：运行五阶段分析时，即使勾选了"增量分析"选项，已经分析过的用例和XMind节点依然会被重新分析并产生费用。

---

## 🐛 根本原因

### 1. XMind节点指纹格式不匹配

**问题**：迁移脚本中构建XMind节点内容指纹时使用的path不正确。

**迁移脚本（错误）**：
```python
# 第66行 - 只使用了节点自己的标题
path_titles = [node.title]
content = f"{title}|{'/'.join(path_titles)}|{note}"
```

**Stage 2运行时（正确）**：
```python
# stage2_extract.py 第311行 - 使用完整的path列表
content = f"{leaf.title}|{'/'.join(leaf.path)}|{leaf.note or ''}"
```

**差异**：
- 迁移时：`搜索小红书渠道分包|搜索小红书渠道分包|`
- 运行时：`搜索小红书渠道分包|投放管理平台1.12.0/分包工具/分包计划/搜索/搜索小红书渠道分包|`

导致指纹不匹配，无法跳过。

### 2. 覆盖率不足

**数据统计**：
- 总用例数：881个
- 已迁移用例：763个（86.6%）
- 总XMind节点：1057个
- 已迁移节点：566个（53.5%）

**原因**：只有生成了反哺候选的项才会被迁移。如果某些用例/XMind在之前的分析中没有生成反哺候选，就不会被缓存。

---

## ✅ 修复方案

### 修复1：更正XMind节点path构建

**文件**：`backend/core/legacy/migrate_cache_to_incremental.py`

**修改前**（第54-72行）：
```python
xmind_node_map = {}  # node_id -> (title, path_titles, note)
for xf in xmind_files:
    tree = load_xmind_tree(project, xf['file_id'])
    if tree:
        for node in tree.nodes:
            # 获取从根到当前节点的路径标题
            path_titles = []
            current = node
            # 简化：直接使用node_id作为路径（因为tree.nodes是扁平列表）
            path_titles = [node.title]  # ❌ 错误
            xmind_node_map[node.node_id] = (
                node.title,
                path_titles,  # ❌ 只包含节点自己的标题
                node.note or ""
            )
```

**修改后**：
```python
xmind_node_map = {}  # node_id -> (title, path, note)
for xf in xmind_files:
    tree = load_xmind_tree(project, xf['file_id'])
    if tree:
        for node in tree.nodes:
            # 使用与stage2_extract.py完全相同的格式
            # leaf.path 是从根到自身的完整路径（含自身title）
            xmind_node_map[node.node_id] = (
                node.title,
                node.path,  # ✅ 完整的path列表
                node.note or ""
            )
```

**修改内容格式构建**（第108-118行）：
```python
if node_id in xmind_node_map:
    title, path, note = xmind_node_map[node_id]
    # 使用与stage2_extract.py第311行完全相同的格式
    content = f"{title}|{'/'.join(path)}|{note}"  # ✅ 使用完整path
    mark_xmind_node_analyzed(cache, node_id, content, ...)
```

## 💡 为什么不是100%跳过？

### 原因分析

1. **反哺候选覆盖率**：
   - 用例：763/881 = 86.6%
   - XMind：566/1057 = 53.5%

2. **为什么有些项没有反哺候选**：
   - 某些用例/XMind可能质量较低，LLM认为不值得提取知识点
   - 某些可能是重复或相似的内容
   - Stage 2的信号抽取是有选择性的

### 这是正常的！

**增量分析的工作流程**：
1. 检查缓存 → 找到763个用例 + 566个XMind节点
2. 过滤已分析的项 → 跳过这些
3. 分析剩余的项 → 118个用例 + 491个XMind节点
4. 更新缓存 → 新增的项也会被加入缓存

**第一次增量分析**：
- 会分析未缓存的项（约$0.50-$1.00）
- 之后缓存会更完整

**第二次及以后**：
- 如果没有新增数据：$0.00
- 如果有少量新增：$0.10-$0.30

## 📝 技术细节

### 指纹计算逻辑

**用例**（stage2_extract.py 第225行）：
```python
content = f"{case.title}|{case.preconditions}|{str(case.step_pairs)}"
fingerprint = hashlib.sha256(content.encode("utf-8")).hexdigest()[:16]
```

**XMind节点**（stage2_extract.py 第311行）：
```python
content = f"{leaf.title}|{'/'.join(leaf.path)}|{leaf.note or ''}"
fingerprint = hashlib.sha256(content.encode("utf-8")).hexdigest()[:16]
```

**关键点**：
- `leaf.path` 是从根到自身的完整路径列表
- 例如：`['投放管理平台1.12.0', '分包工具', '分包计划', '搜索', '搜索小红书渠道分包']`
- 用 `/` 连接成字符串
